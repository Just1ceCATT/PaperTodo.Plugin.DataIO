# DataIO 开发说明

面向开发者与维护者；用户安装、使用和常见问题见 [README](../README.md)。

## 实现边界

- 只使用 PaperTodo 公开的逻辑数据 API（`IPaperTodoHostApi`），不直接读写 `data.json`。
- 导出、导入、更新都在插件会话内编排；所有 `CreatePaper`、`UpdateTodo` 等调用都经 `HostGateway` 切回 PaperTodo UI 线程。
- JSON 导出内容：纸片标题、类型（待办 / 笔记）、可见性、待办列表（文本、完成状态、顺序、提醒、关联纸片）、内置 Markdown 笔记正文。
- 导入策略：默认新建纸片；若同一 `sourceId` 此前由本插件导入过，会进入“更新预览”，每张纸片默认“跳过”，只有显式选择“更新”的纸片才会覆盖本地内容。映射只记录在本机插件状态中，不会修改其他纸片。
- 无法还原：窗口位置/大小、折叠与置顶状态、待办关联的文件或文件夹、其他插件提供的自绘正文。
- 笔记内嵌图片：检测到引用时自动导出为压缩包，正文（JSON 保持 `i:` 引用，Markdown 改为相对链接）与 `images/` 下的原始图片一起保存；无图片时仍输出单文件。
- 图片还原：导入压缩包时校验清单与 SHA-256，逐张调用 `NoteAssets.AppendImage` 获取本机新 ID，再用 `WriteNote(Replace)` 把正文引用映射到新 ID；超过 8 MiB 的图片只保留在压缩包中。
- 更新式导入的安全边界：只有正文引用的图片全部可写回时才替换笔记正文，任一图片缺失或超过上限会跳过该纸片并保留本地内容；更新待办纸片时会同步清除文件中已不存在的“关联纸片”和提醒，Markdown 文件不携带这些数据，因此不做清除。
- 图片预览：预览窗口把整行图片引用渲染为图片块，宽度规则与宿主一致（`{width=…}` 优先，其次 `|百分比` / `|宽x高`，最后按原始尺寸）。导出预览经 `NoteAssets.ReadImage` 读取（单张纸片最多 40 张、合计 32 MiB），导入预览直接复用压缩包内已读入的图片字节；缺失或解码失败时显示占位，不阻塞正文渲染。
- 导入的纸片会归入 PaperTodo 内置的待办 / Markdown 笔记正文，无法恢复为第三方插件正文。

## 项目结构

| 路径 | 说明 |
| --- | --- |
| `DataIoPlugin.cs` | 插件入口，负责状态迁移与会话创建 |
| `DataIoSession.cs` | 生命周期、事件订阅、导出/导入编排、历史记录写入 |
| `DataIoView.xaml(.cs)` | 正文界面：导出 / 导入 / 历史记录三个 Tab |
| `DataIoMiniView.cs` | 贴边胶囊悬停面板（Native MiniView） |
| `Models/` | 状态、历史记录、行数据、导入计划与结果模型 |
| `Services/` | 文件读写、导入解析、身份映射、预览、Markdown 处理 |
| `tests/` | xUnit 测试 |

## 导出 JSON 结构

```json
{
  "format": "papertodo.paper-export",
  "schemaVersion": 1,
  "exportedAt": "2026-11-21T14:30:00+08:00",
  "source": {
    "pluginId": "papertodo.dataio.native",
    "pluginVersion": "1.1.0",
    "apiVersion": "2.3",
    "uiLanguage": "zh-CN",
    "note": "sourceId 仅供溯源与同文件内关联纸片还原；导入时 PaperTodo 生成新 ID。"
  },
  "papers": [
    {
      "sourceId": "45f84292f605429db24dabc25175bee8",
      "type": "todo",
      "title": "周计划",
      "show": true,
      "todos": [
        { "text": "写周报", "done": false, "order": 0 }
      ]
    },
    {
      "sourceId": "c103868b43e147fc94ad56fbbbcabfa4",
      "type": "note",
      "title": "资料",
      "show": false,
      "contentAvailable": true,
      "content": "# 参考资料"
    }
  ]
}
```

`sourceId` 用于溯源、**同一文件内**的关联纸片还原，以及本机导入身份映射；导入时不会作为 PaperTodo ID 使用。

## Markdown 标记

- 本插件导出的 Markdown 含 `<!-- papertodo-dataio:v2 type=todo sourceId=... -->` 注释，按注释分节并还原标题、待办勾选状态、笔记正文与来源身份。
- 导入端同时兼容旧版 `<!-- papertodo:type=... -->` 标记；代码块内的同名标记会被忽略，笔记正文中的标记在导出时自动转义。
- 正文不可读取的笔记使用 `<!-- papertodo-dataio:content-unavailable -->` 标记，回导时会保持“正文缺失”而不是把占位文案写成正文。
- 没有标记的普通 Markdown 会作为一张纸片导入：首个 `# 标题` 作为标题；正文只有 `- [ ]` / `- [x]` 待办列表时识别为待办纸片，否则为笔记。

## 默认文件名

`Services/ExportFileName.cs` 生成：

```text
pt-YYMMDD-HHmm-N张.json
pt-YYMMDD-HHmm-N张.md
```

例如 `pt-261123-1435-3张.json`。时间使用 InvariantCulture，按名称可排序；数量为本次导出的纸片张数。

## 历史记录与悬停面板

- 历史记录保存在 `DataIoState.History`，最多 20 条，只包含时间、文件路径、格式、数量与结果，不包含纸片正文。
- 正文历史页与 Native MiniView 共用同一份历史。
- MiniView 通过 `IPaperMiniViewProvider` 提供，首选尺寸 `340 × 260`，并在 `plugin.json` 的 `miniMaxSize` 中声明上界。
- 悬停面板最多展示 4 条；长文件名中部省略并保留扩展名。
- 导出/导入图标：`E72D`（向外指，导出）、`E8B5`（向内指，导入）、`E81C`（历史）。

## 权限

| 权限 | 用途 |
| --- | --- |
| `papers.read` | 读取纸片列表 |
| `todos.read` | 导出待办 |
| `notes.read` | 导出笔记正文 |
| `papers.create` | 导入时创建新纸片 |
| `todos.append` | 导入带待办的纸片 |
| `todos.update` | 还原顺序、关联纸片与提醒 |
| `todos.delete` | 更新纸片时删除文件中已不存在的待办 |
| `notes.append` | 导入带正文的笔记 |
| `notes.replace` | 更新纸片时替换笔记正文 |

## 状态存储

插件状态由 PaperTodo 托管，位于程序目录：

```text
plugins/data/papertodo.dataio.native.json        # 工作区 1
plugins/data2/papertodo.dataio.native.json       # 工作区 2
... data3 / data4 / data5
```

状态按纸片 ID 保存在 `papers.<paperId>.data`，包含：

- `History`：最近的导入/导出记录；
- `ImportLinks`：`sourceId → 本地纸片 ID` 的导入身份映射；
- 上次导出/导入目录、导出格式、搜索关键字等 UI 偏好。

清理该文件或删除 DataIO 纸片会导致历史与更新映射丢失。

## 构建与安装

需要 .NET 10 SDK 和 PaperTodo 源码仓库。

```powershell
# 退出 PaperTodo 后执行；-PaperTodoRoot 指向 PaperTodo 仓库根目录
.\scripts\Build-And-Install.ps1 -PaperTodoRoot "<PaperTodoRoot>"
```

脚本复用 PaperTodo 的共享构建脚本，发布为 `win-x64`、框架依赖模式，并安装到：

```text
<PaperTodoRoot>\plugins\papertodo.dataio.native\
```

如果 PaperTodo 从发布目录运行（例如 `<PaperTodoRoot>\输出\PaperTodo-v4.0.0-beta2\PaperTodo.exe`），
需要同步到该目录的 `plugins` 根：

```powershell
.\scripts\Build-And-Install.ps1 -PaperTodoRoot "<PaperTodoRoot>" `
  -AdditionalPluginsRoot "<PaperTodoRoot>\输出\PaperTodo-v4.0.0-beta2\plugins"
```

安装后重启 PaperTodo。原生插件不支持热重载。

## 已知工程限制

- PaperTodo 没有重命名普通纸片的 API，更新时不会同步标题；类型也不能从待办改为笔记或反向转换。
- PaperTodo 单工作区最多 200 张纸片，导入前会预检。
- 若开启“已完成待办自动置底/自动清除”，导入后的顺序可能被自动排序调整。
- 导入是逐张纸片提交的部分成功语义：失败不会回滚已创建的纸片。
- 把一张纸片首次切换到本插件正文时，标题会被统一改为“DataIO”；只执行一次。
