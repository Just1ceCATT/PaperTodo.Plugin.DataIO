# 导入身份适配实现

本文说明插件如何通过本地身份映射，实现“再次导入同一来源文件时更新原纸片”。

## 目标

PaperTodo在 `CreatePaper` 时总是生成新 ID，因此同一张源纸片导入到另一台设备后会得到不同的本地 ID。适配层在首次导入时记录两者的对应关系，后续导入据此更新原纸片，而不是反复新建副本。

## 存储

映射保存在插件状态 `DataIoState.ImportLinks` 中：

```json
{
  "ImportLinks": {
    "<sourceId>": {
      "LocalPaperId": "<本地纸片 ID>",
      "Type": "todo",
      "Title": "源纸片标题",
      "LocalFingerprint": "上次导入完成后的本地内容指纹",
      "LastImportedAt": "2026-11-22T15:00:00+08:00"
    }
  }
}
```

- 与 `data.json` 完全分离，PaperTodo热重载不会改写它。
- 按工作区隔离，随 DATAIO 工具纸片的插件状态保存。
- 最多保留 4096 条，解析时清理无效条目。

## 工作流程

### 首次导入：登记

1. 文件中的纸片带有 `sourceId`；
2. 映射中查不到，按新建处理；
3. PaperTodo返回新纸片 ID；
4. 导入及顺序/关联/提醒修复完成后，记录 `sourceId → 本地纸片 ID` 和本地内容指纹。

### 后续导入：命中并更新

1. 按 `sourceId` 查映射；
2. 校验本地纸片仍存在；
3. 校验类型一致；
4. 校验笔记仍由内置 Markdown provider 承载；
5. 比较当前本地内容与记录指纹，标记“本地已修改”；
6. 写入导入计划的更新目标，确认弹窗显示“新建 N 张，更新 M 张”。

### 映射失效

以下情况删除映射，按新建处理：

- 本地纸片已不存在，且没有可回退的历史副本；
- 类型不一致，且没有同类型的历史副本；
- 笔记 provider 不再是内置 Markdown；
- 映射未记录指纹（旧数据）。

### 历史副本回退

每个 `sourceId` 会保留最近 **8 个**指向过的本地纸片 ID：

- 选择“新增”时，映射改指向新副本，原副本压入历史；
- 新副本被删除后，映射自动回退到最近仍存在的历史副本；
- 这样“选择新增 → 删除新副本 → 再次导入同一文件”仍能匹配到原副本并显示差异，而不是重新新建；
- 回退后旧指纹清空，下一次成功导入会重新登记，避免误报“本地已修改”。

## 更新语义

### 笔记

- 使用 `WriteNote(NoteWriteMode.Replace)` 整体替换正文。
- 需要 `notes.replace` 权限。
- 文件未包含正文时跳过更新，避免清空本地笔记。

### 待办

- 按文本匹配本地待办，优先匹配完成状态相同的一条；
- 完成状态不同的匹配项用 `UpdateTodo` 更新；
- 文件中新增的待办用 `AppendTodos` 追加；
- 文件中已不存在的本地待办用 `DeleteTodo` 删除，需要 `todos.delete` 权限；
- 顺序、关联纸片、提醒仍由第二遍修复流程处理；
- 空文本待办不会被删除，避免误删PaperTodo输入行。

### 无法更新

- **标题**：PaperTodo没有重命名普通纸片的 API，保留本地标题，并在结果中提示不一致。
- **类型**：待办与笔记之间不能转换。
- 文件/文件夹关联、图片本体仍无法还原。

## 更新预览与选择

命中映射后，导入前会打开“更新预览”窗口：

- 逐张显示本地现有内容与导入内容的行级差异；
- 每张纸片可选择：
  - **跳过**：本次不导入该纸片，保留本地内容与映射；
  - **更新**：按文件内容更新命中的本地纸片；
  - **新增**：忽略映射，创建新纸片；导入完成后映射改指向新副本。
- 本地指纹与当前内容不一致时，窗口会提示“更新会覆盖本地修改”。

更新预览中每张纸片默认“跳过”，覆盖本地内容必须显式选择“更新”；更新成功后才刷新指纹。选择“新增”或“跳过”只影响本次导入，不会删除原有映射。

笔记正文与本地等价（忽略尾部空行与分隔线）时视为无变化：这类笔记不会出现在更新预览中，也不会计入本次导入。待办仍会保留在预览里，因为差异快照不包含提醒与关联信息。

## 本地修改检测

- 笔记指纹 = 正文 SHA-256。
- 待办指纹 = 按顺序覆盖文本、完成状态、提醒、关联纸片、文件/文件夹关联后的 SHA-256。
- 指纹不一致说明本地自上次导入后被修改过；确认弹窗会提示将被覆盖。

## 设置与权限

新增设置：

- `updateImportedPapers`：是否更新已导入的纸片，默认开启。

新增权限：

- `notes.replace`：替换笔记正文；
- `todos.delete`：删除文件中已不存在的待办。

## 限制与风险

- 映射只存在于插件状态。删除 DATAIO 工具纸片、清理插件状态或重装插件数据后，映射丢失，后续导入会新建副本。
- 映射启用前创建的旧副本没有登记，无法自动关联。
- 不同设备各自维护自己的映射，第三台设备首次导入时仍会新建。
- 导入文件中的 `sourceId` 可以被手工伪造；更新前应查看确认弹窗中的“将更新”标记。
- PaperTodo热重载可能删除映射目标；每次导入前都会校验并清理失效条目。
- 插件状态与 `data.json` 不是同一事务；极端崩溃情况下可能出现“纸片已创建、映射未保存”，下次会重复创建。

## 手工验证

1. 在 A 导出测试文件，导入 B，确认新增纸片。
2. 再次导入同一文件，确认确认弹窗显示“更新已有”，且 B 不产生新副本。
3. 在 B 手动修改纸片内容，再次导入，确认出现“本地已修改，更新会覆盖”提示。
4. 在 A 增删待办、修改笔记正文，再次导入，确认 B 内容同步。
5. 删除 B 中映射目标，再次导入，确认重新创建并登记。
